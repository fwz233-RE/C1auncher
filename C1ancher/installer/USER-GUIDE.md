# C1-Slim 图形批量安装器使用说明

## 当前交付状态

本目录是 Windows x64 图形安装器与外置组件。**以同目录 `BUNDLE-STATUS.json` 和 GUI 的实际校验结果为准**：`READY` 表示完整签名核心及必需组件已组装，可进入设备检查与安装；`NOT_READY` 表示仍缺完整核心包，只能检查 USB／root ADB，安装按钮禁用。单独保留 EXE 或少复制组件均不能完成安装。READY 是本地组件验证结果，不代表已经向当前连接的设备安装，也不保证它的固件基线兼容。

安装器通过 root ADB 安装用户空间组件，不写 bootloader，不格式化存储，也不烧录整机分区镜像。目标为已审核原厂脚本基线的 C1-Slim／MP-D261 MIPS 设备。它不与某台电脑或某个设备序列号永久绑定；单次操作只发往操作员选中的那台设备。

## 2026-09-07 安装成功必须开启深度休眠（2.0.0 源码策略）

Windows EXE 安装器每次安装都先验证配套签名核心及其实际运行进程，再执行该核心的 `c1pkg power enable`，随后独立检查深度休眠开关确实开启。此操作会覆盖已有禁用设置，包括旧安装器标记和空文件；并非只在首次安装默认开启。删除原厂软件前先完成开启和检查，所有安装步骤结束后再检查一次；选择重启时，最后一次检查在重启验收后进行。开启失败、开关未开启、检查命令失败或返回标记异常均报告安装失败，保留恢复暂存目录，不写入成功结果。

受支持硬件要求精确匹配 `ingenic,halley6_v20`、存在 `mpenbatt` 平台设备、`gpio_keys` 唤醒已开启且内核 `mem` 接口可读写。不受支持硬件不能通过此安装成功门槛。安装准备阶段仍保留旧禁用标记，直到配套核心验收后才明确启用；旧 PowerShell 入口的 `-EnableAutoSuspend` / `-DisableAutoSuspend` 策略保持不变。这次补齐仅做离线回归，不触发真实设备休眠或重启测试。

本次授权发布目标为 **2.0.0**，此修订仅完成安装器源码与离线回归；尚未构建正式 EXE、组装安装包、分配序列、签名或部署。后续交付必须将已批准的 2.0.0 完整签名核心与重新编译的 EXE、对应助手整体使用。助手通过本次安装包的 manifest 与 `c1pkg` 哈希绑定当前核心，并要求相同身份的严格 `confirmed` 状态；不会因旧核心“仍有有效签名”就替它启用休眠。受支持硬件上的最终验证不会重新启用已被关闭的偏好；硬件能力丢失时则强制保持禁用并报告失败。

唤醒后若电脑未重新识别 USB/ADB，允许用户手动拔下并重新插入 USB 数据线。产品不要求 USB 全自动恢复，不要求 Wi-Fi 连接触发 USB 修复，也不要求整套 USB 重启兜底。此说明适用于正常使用时的休眠唤醒；安装、升级或文件传输进行中仍须保持供电和连接。

## 2026-09-06 上传异常处理修复

本次电脑端 EXE 保留核心 **1.3.4 / 序列 6**，包含 ADB 双回车换行兼容修复，并补充以下行为：上传时记录文件序号、名称和大小，等待期间每 5 秒提示尚未完成，只有远端摘要校验通过才记录完成。等待提示不代表字节正在增长。单次上传上限仍为 180 秒，不因出现提示而延长。

命令超时同时覆盖进程退出与输出管道读取；只清理本次本地命令，不重启共享 ADB 服务。传输失败立即停止后续安装步骤，不自动重试，不将失败计为成功。界面显示错误摘要，完整异常保存在该次设备记录的 `failure.txt`；失败后的设备日志读取最多等待 5 秒。确认窗口打开期间禁止重复发起安装，异步检测结束时若主窗口已关闭，不再写入已释放控件。

上述修改不能替代设备授权或修复物理 USB 断连。请先恢复同一设备的调试连接，再由操作员主动点击安装；已开始设备端后台任务的失败应先检查日志，不要盲目重复安装。

## 2026-09-06 设备脚本换行修复

修复 Windows 检出后的 `device-open-adb.sh` 含 CRLF、导致设备执行 `set -eu` 报 `illegal option` 的打包缺陷。所有未签名的设备 shell 脚本和 Neofetch shell 配置在打包时统一将 CRLF 转为 LF；设备执行用文件拒绝 BOM、残留 CR、NUL 与无效 UTF-8。合法的无末尾换行文件保持原样，不添加字节。EXE 在任何安装设备命令之前检查这些格式，不能仅靠重算哈希绕过格式错误。

签名核心 1.3.4 / 序列 6 的完整 13 文件及原厂 USB 基线保持字节不变，既不转换也不重新签名。交付检查对完整包内 12 个设备 shell 脚本/配置做 Linux shell 语法检查，并只运行 USB 脚本的 `#!/bin/sh`、`set -eu` 两行前缀来复现和排除本次错误，不在电脑执行完整安装脚本。默认不备份原厂学习软件、验证核心后直接删除的流程不变。

## 2026-09-06 核心上传权限修复

设备实测显示 Windows ADB 将核心清单、签名、公钥及二进制上传为 `666` 权限，目录为 `777`。签名验证器会拒绝可被组或其他用户写入的文件，导致 `secure file metadata rejected`。本版在任何安装辅助步骤之前，仅对本次生成的核心暂存目录检查类型和链接，将三个目录设置为 root:root / `700`、13 个文件设置为 root:root / `600`，检查实际权限并重新核对全部文件哈希，再进入原有签名验证流程。

权限准备不修改签名内容或信任公钥，不放宽验签规则，不修改历史安装目录。权限、链接或重新校验失败立即停止。开机 ADB 和壁纸已成功安装的同版本设备可通过原有幂等检查；安装仍需由操作员点击，原厂软件只在新核心验证运行正常后删除。

## 2026-09-06 原厂清理与安装收尾修复

新核心已正常显示桌面，但第 7 步出现 `find: unrecognized: -links`，表示停在原厂软件删除前的安全检查，而不是核心安装失败。本版改用设备 BusyBox 支持的逐文件 `stat` 链接数检查；任一检查失败即产生拒绝结果并停止扫描，不依赖 BusyBox 会丢失早期批次错误的批处理退出码。仍拒绝符号链接、特殊文件、多硬链接和嵌套挂载，保留中文、空格与换行文件名。预检先验证工具能力及成功、失败两种检查结果，避免不兼容到清理阶段才发现。

同版本核心的收尾重试使用本次已上传并验证的安装脚本，不依赖历史暂存脚本。只有已登记核心通过完整性检查才可启动；仍需确认真实主页进程匹配安装包，才能删除原厂软件。后台启动和重启后的启动就绪检查都有等待上限。重启命令失败会立即报告；启动编号必须合法且发生变化。只有最后暂存目录清理成功，才写入安装成功结果。

本版完整沿用首次引导顺序修复后的 13 文件签名封装、核心 1.3.4／序列 6 和原信任公钥，不重新签名或替换已安装的核心。修复和本地仿真测试不自动删除设备文件或重启设备；安装由操作员点击，整机与冷启动仍需实际验收。

## 2026-09-06 主页派生进程识别修复

主页打开内置终端后，会派生一个持续运行的终端管理进程，它没有执行新的可执行文件，因此 `/proc/<pid>/exe` 与主页完全相同。服务任务也可能使用同样的派生方式。旧版将所有同镜像进程直接计数，要求结果必须恰好一行，会把正常的主页与辅助进程误判为多个主页。旧失败日志没有保留进程关系，单凭日志不能确认某一次现场失败一定由此引起。

新版先解析当前核心的实际路径，读取主页及启动器的实际运行镜像摘要、PID、父 PID 和启动时刻。必须存在唯一的可信启动器，以及它直接启动的唯一主页主进程；其余同镜像进程必须能沿父子关系追溯到这一个主页，并逐个通过摘要检查。独立启动的第二个主页、多个启动器、其他版本、已删除镜像、摘要不符、关系断裂或读取失败仍拒绝通过。读取前后检查身份是否变化，且主页和启动器身份须间隔 2 秒连续两次一致。等待上限仍为 60 秒。

这项检查用于删除前、删除后及重启后，不修改核心签名、设备脚本、信任公钥或已安装核心。等待失败时会记录具体原因及最后一次只读进程快照，并保存 `running-process-before-removal.txt`、`running-process-after-removal.txt` 或 `running-process-after-reboot.txt`，避免只留下笼统的“没有检测到唯一主页”。此修复只经过离线回归和私有进程仿真，不代表原失败设备已通过重试验收。

## 开启 ADB（热点辅助）

设备尚未开放 ADB 时，可点击安装器“开启 ADB（热点辅助）”。此按钮独立于组件校验、设备选择和安装授权，不会开始安装。

1. 在提示窗口点击“打开 Windows 移动热点设置”，开启 **2.4 GHz** 热点，让设备连接电脑热点，并插上 USB 数据线。
2. 确认可信脚本路径。安装器优先使用 EXE 同级的 `adb_admit_local.py`，否则默认使用 `D:\c1slim\adb_admit_local.py`；也可点击“选择脚本…”指定其他位置。本版只内置启动入口，Python 脚本和依赖仍在外部，原脚本不作修改。
3. 设备 IP 可留空，沿用当前脚本按 MAC `58-C5-87-15-F1-49` 自动发现的行为。换设备时，请填写 Windows 热点客户端列表中的当前 IPv4，避免沿用另一台设备的 MAC 或过期 DHCP 地址。
4. 点击“确定，启动脚本”，接受 Windows 管理员权限提示。安装器会在独立的 PowerShell 窗口运行脚本；取消提示不会运行脚本。需要 Python 3.12 和 `cryptography`、`pydivert==3.1.3`，缺少时终端会提示，不自动下载或安装。
5. 看到 `READY` 后，进入设备“关于设备”的版本信息项目，在约 5 秒内完整按下并松开 Enter 10 次。等待 `APPROVED` 和 `cleanup_complete=true`，再回安装器查看或刷新 USB 设备。打开终端本身不是放行成功证明。

程序正常退出后终端保留输出，便于看错误；确认清理完成后关闭即可。中途停止请按 Ctrl+C 并等待清理，避免强制结束。旧辅助终端未关闭时安装器阻止重复打开；关闭安装器不会强制结束独立脚本。此按钮不会关闭共享 ADB 服务，不修改签名或信任公钥，也不会执行安装、删除或重启。

完整使用说明和排障见现有的 `D:\c1slim\adb.md`（移动脚本时建议一起保留）。脚本目录的 `adb-admit-plaintext.log` 可能包含账号和设备标识，分享前需脱敏。仅用于本人拥有或已获授权的设备。

## 操作员使用（READY 完整包）

1. 将整个发布目录复制到 Windows 10/11 x64 电脑并解压到普通本地目录。保留 `C1SlimInstaller.exe` 与同级 `payload`，不需要单独安装 .NET。电脑仍需正确的设备 USB 驱动。
2. 双击 EXE，查看组件检查结果。请使用维护者通过可信渠道提供的完整包；包内 SHA256SUMS 只是传输校验，不能单独证明来源。
3. 在设备上完成 USB 调试／原厂开发授权，插上 USB；尚未开放 ADB 时，可使用上述“开启 ADB（热点辅助）”入口。已有连接时，安装器可以请求标准 `adb root` 并等待同一台设备恢复连接。热点辅助仍需外部 Python 环境、正确网络连接和设备端手动触发，不保证所有固件适用。
4. 选中状态为 `device` 的设备，确认序列号，勾选操作授权。`unauthorized` 需先在设备端授权，`offline` 需处理连接。
5. 点击“安装到所选设备”。建议保持“安装后重启并验证”勾选。安装过程中保持供电，不拔线、不换组件目录。
6. 看到本台检查通过后，人工确认主页显示、实体按键、包管理器刷新、首页核心更新入口，再换下一台。按钮不会自动对刚插入设备进行破坏性安装。

每台操作独立完成：

- 检查 root、型号、只读根分区、原厂启动脚本与组件完整性。
- 上传并重新核对文件摘要；不安装普通应用。
- 默认不备份原厂学习软件，不创建或拉取原厂目录备份；此行为直接内置于安装流程，没有备份开关。
- 安装开机 ADB 支持、默认附属文件、主页 `C1ancher`、包管理器 `c1pkg`、启动器 `C1ancher-launcher`、更新器 `c1updater` 与启动保活／恢复组件。
- 配置应用仓库、核心更新地址与公开验签公钥。
- 复制电脑端开发工具到 `/storage/mtp/C1DeveloperTools/<内容摘要>/`。
- 确认已签名核心及实际运行的主页进程与安装包一致后，直接删除 `/usr/bin/d261` 原厂学习软件；不删除普通应用、用户数据或历史备份。中文、空格和换行文件名不再需要通过备份清单检查。
- 选择重启时，检查同一序列号的新启动编号和重启后的核心状态。

## 开发者使用

通过文件传输将设备 `C1DeveloperTools` 下面一个完整版本目录复制到电脑。包含：

- `c1publish.exe`：Windows x64。
- `c1publish-linux-amd64`：Linux x64。
- `c1publish-linux-arm64`：Linux ARM64。
- `README.md`、`server.url`、`repository.ed25519.pub`：说明、公开地址、公钥。

发布工具从**自身所在目录**读取地址和公钥，因此把该目录完整复制到其他电脑仍可使用。Linux 如丢失可执行权限，按目录中 README 执行 chmod。发布工具在电脑运行；上传的应用才是为设备编译的静态 MIPS 程序。

官方服务器已于 2026-09-06 启用开放发布。开发者自行选择尚未占用、未受保护的应用 ID，使用 `-open` 发布，不需维护者逐人创建 ID 或上传令牌。ID 是应用的唯一名字，不是要向维护者申请的账号。公开公钥用于验证仓库索引，不需要申请或保密。当前公开 HTTP 地址上传须显式接受 `-allow-insecure-http`；具体命令见随设备工具附带的 README。

本包包含 `publisher-bundle-live-20260906` 的完整六个公开文件，可以直接使用已经上线的服务；本次重新打包不修改或部署服务器。开放应用允许任何人发布更高版本，并非首发者独占；已有受保护应用与核心更新接口保持原有权限边界。设备安装完仓库配置后可独立联网使用，不依赖安装电脑；发布成功也不会强制为其他设备安装应用。

## 日志、失败与恢复

“打开安装日志”进入本次运行目录，默认位于 `%LOCALAPPDATA%/C1SlimInstaller/runs/`。其中有会话日志、每台的输入组件快照及结果，没有本次原厂软件备份。保存关键记录后再自行归档，不要在操作期间清理。

本版安装器不创建原厂恢复副本，也不提供原厂恢复命令。已有历史备份保持原样，但安装器不会依赖或验证它们；删除后不能依靠本次安装记录恢复原厂学习软件。失败时保留 USB 连接，查看明确失败步骤；安装器保留自己创建的设备暂存目录与后台日志线索，不会将失败计为成功。已经修改到哪一步以日志为准，不能把所有失败都理解成“设备完全没改”。

已有其他版本的已登记核心由设备更新器升级；批量首次安装器拒绝重置这类设备的更新历史。签名核心的启动恢复组件仍然保留，它与已取消的原厂软件备份是两项不同功能。

## 维护者：构建与换版本

- GUI 构建：运行 `installer/build-installer.ps1`，需要 .NET SDK 8。输出到新目录，不覆盖既有发布。
- 组件组装：见 `installer/BUNDLE-MAINTAINER.md`，使用 `installer/build-bundle.py`。需要 Python 与 cryptography，维护工具不运行 ADB。
- 模板补齐：取得真实的完整签名 enrollment 包后，使用 `build` 加 `--enrollment-dir`，生成新的 READY 交付目录；不通过修改状态文件把模板变成 READY。
- 日常换版本最简单的做法：维护者提供已经组装、校验好的新 `payload` 文件夹，操作员关闭 EXE 后整体替换该文件夹，再打开重新校验；EXE 不需要改变。
- 已有 READY 包换核心版本：关闭安装器，整体替换 `payload/enrollment` 为同一核心公钥签署的新完整 13 文件目录，然后运行 `refresh-manifest` 重算外层清单，再在 GUI 重新校验。**EXE 无需重编**。
- 只替换某一个编译文件会破坏签名绑定而被拒绝。四核心文件、release 清单与签名、bootstrap 清单与签名是同一次发布的完整单元。重新计算 SHA256SUMS 不能代替签名。

## 验收范围

安装器执行了本地编译、离线签名／清单与模拟安装测试；此前已启动图形界面进行设备列表扫描。本次组件更新与重新打包不向设备安装、不请求 root、不重启设备，也不部署服务器。READY 和离线测试通过不等于新设备首次安装已经验收。多台新设备、其他电脑、USB 驱动差异与屏幕按键仍需用完整 READY 包实际验收；先验收一台，再逐台批量安装。
