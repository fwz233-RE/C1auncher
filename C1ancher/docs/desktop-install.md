## 包含什么

- 296×152 单色中英文桌面、Wi-Fi、包管理、窗口终端、进程、关于、设置及四种锁屏外观。
- 独立 `c1-ime-service` 和纯 C 输入法接口。终端、锁屏文字编辑、包管理中文检索共用同一服务；Wi-Fi 密码不经过输入法。
- 输入法作为 `c1-ime` 应用包安装：`/storage/c1/apps/c1-ime/current`；独立用户词库：`/storage/c1/ime`。不会把约十余 MiB 的词典塞进只剩约 12 MiB 的 `/usr/data`。
- 运行词典由**真正的 MIPS 服务在 QEMU 中生成**，不是复制 x86 编译的字典。桌面以 `--prebuilt-only` 启动，缺少预编译资源立即失败，不在设备上悄悄回退到昂贵的字典编译。
- `c1pkg install-local REPOSITORY_DIR ID`：先用设备已信任的应用公钥验证离线索引，再校验包的大小/哈希，使用原有受限解包和原子安装事务。离线索引不覆盖线上仓库的 URL、缓存或序列；应用版本仍防止普通安装降级。

核心签名包仍然只有 `C1ancher`、`c1pkg`、`C1ancher-launcher`、`c1updater` 四组件。输入法用独立的应用仓库签名，避免修改已有核心协议及恢复验证器。

## 先构建，不接触设备

要求 Windows PowerShell、WSL Ubuntu-22.04、OpenSSL，以及已经用于 MIPS 构建的编译器/QEMU/依赖源码。两个**已有**私钥必须在整个仓库之外；不创建新密钥、不替换设备公钥。

从仓库根目录运行（序列 `12` 只是示例，必须大于待安装设备已接受的序列；不要复用已签过其他内容的序列）：

```powershell
$epoch = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
.\C1ancher\scripts\build-desktop-bundle.ps1 `
  -Sequence 12 -SecurityEpoch 1 -ImeVersion 0.1.0 `
  -SourceDateEpoch $epoch `
  -OutputDirectory D:\c1slim\C1ancher\build\desktop-bundle\12-dev `
  -AllowDirtySource
```

`-AllowDirtySource` **仅用于你自己的开发设备**，产物记录 dirty 来源；不用于公开或生产发布。正式发布应先选择并提交允许发布的源码，通过清洁构建。不要顺手提交安装器、服务端、发布器或 InkWars 源码。本脚本不会提交或推送。

可显式指定 `-CoreSigningKey`、`-AppSigningKey`、`-OpenSslPath`、`-WslDistribution`。默认使用现有本机签名密钥位置。**修改输入法程序或词库后也要提高 `-ImeVersion`**（例如 `0.1.1`）；同版本安装是跳过，不会自动覆盖或修复旧文件，安装脚本会在内容不符时阻止准备新核心。

构建脚本：

1. 增量构建 MIPS 输入法，预编译运行词典，用全新用户目录验证“你好”“中国”、候选翻页和缺失资源拒绝。
2. 使用**新的独立核心构建目录**完成主机测试、生命周期测试和静态 MIPS 构建，不清空已有 `build/`。
3. 调用既有核心和应用签名构建器，随后离线复核签名、ABI、文件大小/哈希及包内布局。
4. 生成 `core/`、`apps/`、`runtime-report.json` 和本说明；生成的公钥与构建证据路径在输出中列出。

中途失败的目录不会冒充成功产物；改用新的输出目录重试。公开分发前还须完成 NOTICE 所列对应源码、静态链接组件重链接等许可义务；收集许可文本不等于已完成全部发布义务。此开发构建不会创建公共源码附件。

确认已保存工作、电源稳定、有物理恢复途径；提前备份重要媒体。加入以下参数后才会联系并修改**指定序列号**的设备：

```powershell
python .\C1ancher\scripts\prepare-desktop-install.py `
  --bundle D:\c1slim\C1ancher\build\desktop-bundle\12-dev `
  --core-key <已经信任的32字节核心公钥路径> `
  --app-key D:\c1slim\C1ancher\config\app-repo\repository.ed25519.pub `

  --install --adb <adb.exe完整路径> --serial MagicPen-967fa9 `
  --backup D:\c1slim\build\device-backups\desktop-before-14
```

备份目录必须是新目录。此模式会：

- 校验 root ADB、根分区只读、`/storage` 已挂载、两套公钥与设备匹配、当前核心可验签，更新事务处于 `confirmed` 或完成回退后的 `idle` 状态、没有待处理的启动/回退/重启标记，以及新序列/剩余空间。
- 备份 `/etc/app_daemon`、`/usr/data/c1` 和已有 `/storage/c1/ime`。它不是整机或媒体全备份，运行中的数据库备份也不是一致性快照；重要应用数据应先退出应用并单独备份。
- 传输至独立暂存目录，逐文件复核 SHA-256，然后用设备固定恢复验证器再次验证新核心清单。
- 仅在上述认证之后执行新签名核心中的 `c1pkg`，离线安装输入法。随后才调用原更新器 `prepare-local` 准备桌面核心。
- **不重启、不强停任何应用、不挂载根分区为可写、不覆盖启动脚本、不清理历史回滚代、不改公钥。**

输入法安装失败不会准备新核心；核心准备失败时已经完整安装的输入法包会保留，原核心仍可使用。输入法与核心属于两个独立事务，不宣称跨两套更新器全局原子；安装顺序确保先具备依赖再准备桌面。失败后的专用暂存目录保留供排查，不自动清理可能仍被事务引用的内容。

确认工具报告 runtime installed / core prepared 后，保存工作，通过设备原有核心更新确认界面重启（已有 `c1updater tui-prepared` 入口）。不要手工改 `current` 链接或强制 `confirm`；原监督器负责新核心健康确认和失败回滚。

- 终端固定全屏，只保留公共顶栏；不提供小窗、最大化或紧凑字体切换。
- 主页方向键移动选中项，主页表情键无动作，确认键进入，不使用方向键直接启动入口。
- 应用列表上下选择、左右切换浅底的本地/商店标签，四角括号标记当前页；验证、刷新和任务状态移至页脚，普通列表为五行。浏览状态按字母定位，有限中文首字母映射和重复循环保留。本地确认打开，商店确认进入管理，单按 Shift 进入管理；移除“表情搜索”提示。后台刷新不占用导航，完整搜索仍可通过兼容入口使用。

- 锁屏可选择壁纸、保留画面、文字、月历；文字自动换行，在完整显示的前提下尽量放大利用屏幕。关闭刷新只保持显示，不等于整机零功耗。
