# 中文图形包管理器

## 入口与交互

桌面 APP 默认执行 `c1pkg gui`。这是 296×152 的原生黑白图形界面，不再把 ANSI 字符框当作包管理界面。独立 PTY 只负责桌面的物理按键转发，管理器持有应用运行锁及独占屏幕锁；普通终端会话保留，桌面不会覆盖图形帧，等待期间不会进入自动休眠。

- 默认打开“已安装”，即使没有安装任何应用也保留该页；左右切换“可下载 / 已安装”，上下选择应用。
- 在“已安装”按 Enter 或 OK **直接启动所选应用**；在“可下载”按 Enter 或 OK 打开详情，左右选择“打开 / 安装 / 更新 / 卸载 / 返回”，确认执行。已安装应用的更新、卸载仍从“可下载”详情操作。
- **空格只刷新列表**，原 R 快捷键已移除。更新软件由详情页单独确认，浏览和刷新不会暗中安装软件。
- 列表内连续输入 ASCII 软件名称前缀快速定位，忽略大小写，并同时匹配应用 ID（中文名可通过 ASCII ID 查找）。匹配优先级为 **完整应用 ID > 完整显示名称 > 首个前缀匹配**，同一优先级保持当前列表顺序。例如 `P` 可选中首个 P 开头的应用，继续输入完整 `piano` 时一定优先选中 ID 为 `piano` 的软件，不会被前面的 `Piano Lessons` 或其他同名前缀抢先匹配；列表本身不被过滤，也不改变原排序。
- 前缀最多 40 字符；停止输入 1.5 秒自动清空，并明确提示“定位已超时清空 · 保留当前选择”。退格（BS / DEL）删除一个字符，Ctrl-U 清空；Back / Esc 有前缀时先清空，没有前缀时退出。方向键、切换列表、刷新也清空前缀；成功确认前先校验输入再清空。**无匹配时保留前缀及原选择，但禁止 Enter/OK 启动旧项目或进入其管理页**，同时提示修改或清空后再确认。通过退格纠正、主动清空或看到超时清空提示后，可再次确认当前选择；确认键本身不会静默清除无匹配输入。
- 所有 ASCII 字母（包括 R、Q）在列表中都用于定位。退出使用 Back / Esc 或 Ctrl-C；详情页和网络等待期间仍可用 Q 或返回取消。软件名中的空格不能用于前缀输入，因为空格保留为刷新键；本功能不提供中文输入法或拼音转换。
- 卸载有二次确认，默认选中“返回”，提示会删除应用的所有已安装版本。
- 界面保留三条软件行、独立状态/前缀区、页内位置及操作提示。倒计时只在秒数变化时重绘，相同帧跳过，避免每秒请求全屏刷新。
- `c1pkg tui` 保留终端兼容入口，同样默认已安装、回车启动、空格刷新、前缀定位；为保持旧入口既有业务语义，**TUI 的空格仍会刷新并批量更新已安装应用**，GUI 的空格则只刷新列表。核心更新界面等其他模块不在此次改动范围。

### 输入路径

桌面将字母与空格通过独立 PTY 转发，Enter / OK 转为终端回车，物理删除键转为退格，Back 转为 Escape。包管理器的 GUI、TUI 共用 `tui_model.c` 中的逐键解码和前缀状态；一次读入只消费一个键，避免快速输入 `PI` 或 `PI` 紧接回车时丢失后续字符。方向键、翻页键的转义序列作为完整控制键处理，不参与名称匹配。此次没有修改桌面按键转发代码。

## 中文

界面和软件名、作者名按 UTF-8 解码，按像素宽度截断完整字形，不切断汉字字节。内置 16 像素高字库覆盖常用简繁汉字、CJK 基本区及扩展 A，不依赖设备字体、FreeType 或 locale。罕见的 Unicode 补充平面汉字显示替代字形。

客户端索引解析和服务器名称校验同步接受中文，保持原协议的 **40 UTF-8 字节**上限，继续拒绝控制字符、格式/双向文本控制符、非法 UTF-8 和首尾空白。ASCII 应用 ID、路径、签名与哈希校验规则不变。服务器源码的中文发布校验变化需要部署后才对在线发布生效。

字体来源、可复现生成方式和 SIL Open Font License 1.1 见 `third_party/pkg_font/README.md` 与 `LICENSE.txt`。完整版权和许可已内嵌进 `c1pkg`，可离线执行 `c1pkg font-license` 查看，因此四组件签名核心更新也携带许可；常规分发另附这两个文件便于阅读。

## 首次使用与离线

先验证 `/storage` 确实挂载、已存在的父目录不是符号链接且属于同一存储设备。仅缺少 `/storage/c1` 或 `/storage/c1/apps` 时，读取已安装应用返回成功的空列表，不创建目录，也不阻止服务器目录显示。目录到实际安装时才按原存储流程创建。

真实的挂载、权限或目录可信性错误仍会报告，绝不把它们伪装成“没有安装软件”。图形界面此时保持服务器列表可见，但禁用安装、更新、卸载与打开操作，提示检查存储。若以前已有本地列表则保留最近快照。

经过签名验证的缓存会在网络操作前展示。网络刷新失败保留缓存/现有列表；基于离线列表执行安装或更新时，必须先重新验证服务器索引，并按应用 ID 重新查找，不能用旧数组位置或未验证的软件记录安装。

## 请求间隔与重试

仓库源码中查到的是下载并发、队列和共享带宽限制，排队最多 120 秒，拥塞返回 503 和 `Retry-After: 5`。未找到可确认的每分钟请求次数配置，因此客户端没有硬编码或宣称匹配某个未知次数。

- 所有传输串行，并共用本进程的下一次允许请求时间，包括索引、签名、软件包、后续点击以及固定 IP 备用地址。
- 响应的 `Retry-After` 支持秒数和 HTTP 日期；成功响应也会约束下一次请求。日期优先参考响应的服务器 `Date`，降低设备时钟误差影响。
- 界面显示“等待 N 秒后自动继续”，到时自动发起下一次请求。取消后在同一进程中保留尚未结束的冷却时间。
- 没有服务器等待头时，一般响应留出 1 秒客户端请求间隔；临时网络/服务器失败按有界退避重试。此间隔是保守的客户端节流，不代表服务器每分钟配额。
- 每个地址每次传输最多尝试 4 次；取消、本地 I/O、超限、签名/哈希错误不会作为普通临时网络故障无限重试。429/503 耗尽重试也不会立即切换同一服务器的 IP 地址绕过限流。
- 元数据每次网络传输最多 45 秒，软件包每次最多 600 秒。服务器要求的等待与网络传输超时分开，不再将 60/75 秒等待截成 30 秒或被旧的 45 秒总预算提前终止。
- 自动等待上限为 3600 秒。超过上限会结束当前自动操作，保留服务器给出的截止时间，不缩短等待后提前请求。
- 冷却状态当前为进程内状态，不跨进程/重启持久化，也不是设备上所有其他软件的全局网络调度器。HTTP 重定向内部的请求由 curl 处理。
