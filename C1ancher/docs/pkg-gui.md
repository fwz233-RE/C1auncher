# 应用 GUI：持久搜索与异步商店刷新

2026-09-23 的统计显示调整已随核心序列23刷入 `MagicPen-967fa9`：统计只在商店列表和详情显示，中文统一为“次数”/“安装次数”和 `N次`，本地页隐藏统计标题、数值和占位符；真机最终状态为 `generation=127 phase=confirmed sequence=23`。底层同设备同应用重复安装/升级只计一次不变。

`c1pkg gui` 是 296×152 原生黑白应用界面。桌面只通过独立 PTY 转发按键，GUI 持有应用运行锁和屏幕独占锁；不使用 ANSI 字符框，不启动自己的 Rime 实例。`c1pkg tui` 是独立兼容入口，此文的搜索和异步刷新行为只适用于 GUI。

## 页面和按键

- 默认进入**本地**，离线也显示已安装应用。**左键到本地，右键到商店**；上下正常导航，两个页面保存各自的选择及滚动位置。
- **本地页确认**：状态为“可更新”时进入管理并提示“有可用更新，是否更新？”，默认选中取消；没有更新时直接打开所选应用。已验签的离线缓存、刷新中保留的列表同样遵循显示状态，不会显示可更新却直接启动。**商店页确认进入管理**，不会直接安装或启动。两页浏览状态都可**单按并松开 Shift**（向上箭头键帽）进入管理；安装、更新和卸载在其中明确选择，卸载还需再次确认。详情管理不占用字母键。
- 工具栏右侧显示 Shift 箭头和“管理”，不再显示不可用的“表情搜索”。普通用户键盘层仍保留原语义，仅实际前台 `c1pkg gui` 接收管理事件；组合键释放不会触发管理。
- 完整搜索作为兼容入口保留：`/` 打开，旧 PTY 的 `0x09` 字节可切换，`Shift+Space` 可进入中文搜索。字节解析测试不等于实机表情键可用，页面不再宣传该实体键。搜索编辑中单按 Shift 不打开管理或丢弃文字。
- 搜索是持久的**子串筛选**，同时检查显示名称与 ASCII 应用 ID；ASCII 不区分大小写，中文按完整 UTF-8 原样匹配。浏览状态的字母定位只看当前可见结果，中文名称使用内置拼音首字母表；名称、作者、版本来自已验签元数据，不自动翻译，也不伪造安装次数。内部服务包 `c1-ime` 保留安装能力，但不显示在本地或商店列表中。
- 浏览状态的字母会定位应用：英文名称或 ID 按首字母匹配，中文名称按内置拼音首字母匹配；同一字母在 1.5 秒内重复按键循环匹配项。它与完整搜索筛选是两种不同操作，方向键始终只负责导航。
- 编辑时空格是文字，退格删除一个完整 Unicode 字符，Ctrl-U 清空；**确认先结束编辑并应用筛选，不直接启动**。再次确认才操作当前可见结果。零结果时确认无操作，不会误启动以前的选中项。
- 返回逐层处理：关闭搜索编辑/输入法，清除已应用筛选，最后退出应用列表；输入错误提示先被关闭。详情返回列表、卸载确认返回管理详情。Home/Ctrl-C 为直接退出。
- 列表非编辑状态的**空格仅请求后台刷新**，不会批量更新。正在刷新时的重复请求合并为同一个任务；切页不隐式发起新请求。

## 中文输入法

搜索框内 `Shift+Space` 切换中文输入，通过 `ui/input_method.c` 和公共 C SDK 连接 `/run/c1-ime/socket`。支持 CSI-u `ESC[32;2u` 以及 xterm `ESC[27;2;32~`；转义序列增量解码，不等待后缀阻塞事件循环。

GUI 本地绘制预编辑和最多五个候选；字母、空格、数字、确认、方向键按顺序交给输入法。只有通过有效响应明确标记未消费的按键才进入 GUI 搜索/导航。候选提交作为整段 UTF-8 原子追加，搜索上限 40 UTF-8 字节；非法、截断、控制字符及超限提交拒绝，并丢弃可能误执行的后续确认。

STATUS 就绪校验、序号检查、5 秒请求期限、队列满和断线的失败关闭行为保留。输入法连接仅在搜索焦点内使用；关闭搜索、进入详情、安装、启动应用和退出时清理连接。服务不确定的按键不会重放。GUI 无密码字段，公共应用搜索不会占用桌面密码输入焦点。

## 布局与状态

- 顶栏统一调用 `ui/chrome.h` 的 `c1_chrome_header`：y=0..17，左侧为当前本地/在线应用总数，详情页改为被管理的应用名，右侧只有 `HH:MM` 和 `N%`；页面标签、搜索、网络状态均不放在顶栏。
- y=18..35 为白底黑字标签行：本地/商店各占约64px，选中标签使用与桌面、电池页一致的四角括号，替代原实心三角；右侧保留直接绘制的 Shift 箭头和管理提示。仅商店显示安装统计列标题“次数”/“Inst”，本地隐藏标题、列表数值和管理详情统计。商店名称列仍为 150px，状态列位于 x=164、宽 72px，统计列位于 x=244、宽 42px；本地把空出的 50px 让给名称列（宽 200px），状态列移至 x=214、保持 72px。没有整条黑底工具栏。
- 普通列表从 y=37 开始显示五行，每行 19px；选中行是完整直角黑底白字，黑底四边连续，没有白色挖角，标签的四角框不受影响。Shift 管理图标为水平对称的13×14像素箭头，在16像素文字行内上下各留1像素，距离“管理”文字4像素。原上方状态行已实际让给列表，不保留空白占位。只有搜索编辑或已应用筛选时才在 y=36 显示搜索字段，列表从 y=54 起显示四行。中文输入法可见时保留两行结果，预编辑 y=93、候选 y=113，最多五个候选互不覆盖。
- 页脚分隔线 y=132，信息状态 y=135。优先显示未确认的输入错误、存储不可用、安装操作进度、后台刷新进度，之后显示操作结果、商店验证或离线/未知状态；短提示“空格刷新”只在适用的信息后显示。输入错误独立保存，即使后台刷新成功也不会被验证成功文案覆盖。普通列表不再常驻“确认打开/返回”等教学；管理详情仍保留必要的确认和取消说明。
- 默认字体为 16px。详情标题位于 y=18 以下；标签、名称、状态、统计、搜索和候选均按实际字体宽度分配并裁剪，完整 UTF-8 字符后追加 `...`。商店统计中文显示 `0次`/`7次`、详情“安装次数”，英文使用 `Inst`/`Installs`；未知值在列表显示 `--`、详情显示“暂无统计”/`unavailable`，与明确的零区分。本地详情隐藏统计但保留原按钮位置，卸载确认警告在两页都保留。这里仅改变显示，底层 v2 仍按同设备同应用只计一次，后台上报、重试与成功安装后触发时机不随标签页或显示隐藏改变。长错误只裁剪页脚，不挤占列表或搜索。
- `/usr/data/c1/desktop.conf` 的 `language` 控制页面文案，`C1_UI_LANGUAGE=zh/en` 可覆盖。应用名称原样显示，中文和英文应用可同时出现在同一列表。
- 时间使用 `utc_offset_minutes`，合法范围 -720..840 且为 15 分钟的倍数，默认 480（UTC+8）；不使用进程 `TZ` 替代配置。时间最多每秒检查一次，电量最多每 30 秒使用有界非阻塞读取 `/sys/class/power_supply/battery/capacity`；缺失/非法电量显示 `--%`，绝不伪造数值。相同帧不重绘。

## 真正异步刷新

私有头文件 `src/pkg/gui_refresh.h` 不增加链接依赖。进入 GUI 后先读取本地应用，随后 fork 独立刷新子进程：

1. 子进程重新验证持久缓存，将准确的已验证内存快照通过匿名结果管道交回；缓存读取和签名运算也不阻塞键盘线程。
2. 同一子进程调用原 `c1pkg_repo_refresh`，完整执行下载、Ed25519 验签、序列防回滚及原子缓存提交。
3. 父进程同时轮询键盘、输入法、结果与进度管道。真实等待/重试消息从独立的有界进度管道传回；消息可合并，但完整结果不能丢弃或截断。
4. 最终结果只有在收到完整结构并成功回收指定子进程后才能授权安装。缓存结果仅浏览；网络失败、异常退出、取消及不完整结果保留原列表并禁止新安装。
5. 更新列表按稳定应用 ID 恢复两页选择，不让新索引的数组位置改变当前操作目标。

本地“可更新”提示与显示状态一致，不以本次在线刷新是否成功作为显示前提。该提示不是安装授权：正在刷新或仅有离线缓存时明确选择更新/安装，只提示等待验证完成后再次确认；**不挂起一个稍后自动安装的请求**。用户可以继续选择其他应用，完成刷新后必须再次确认当前结果；若名称或版本已经改变，也必须重新确认。安装仍走原签名、哈希校验、防降级、存储和事务接口，安装与刷新写入不会并行。

返回退出或启动本地应用时关闭取消管道。子进程在原进度回调中看到 EOF/HUP，原传输层负责终止并回收其 curl 进程组，并持有 `repo.lock` 清理自己拥有的临时文件；父进程只回收自己保存的 PID。不会使用 `kill(0)`，不会信号广播到安装进程，也不会从父进程删除共享 `index.tmp` 等文件。这样后继刷新不会被前一个任务的清理误删。

子进程启动时关闭继承的屏幕、运行锁、输入法和终端 fd；保留诊断 stderr，stdin/stdout 指向 `/dev/null`。管道均设置 CLOEXEC，父端非阻塞；重复启动/取消的 fd 及进程泄漏有独立回归。
