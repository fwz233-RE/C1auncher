## 2026-09-22 23:10 新需求与真机原因

用户明确要求同一设备对同一应用重复安装只算一次，升级也不再增加。该口径与原 v1“每次成功安装事件”不同；旧协议不携带稳定匿名设备标识，不能从 token 或源 IP 推断同设备，更不能直接把已有事件次数改名为设备数。v1 接口、数据库与旧设备原行为继续保留；v2 新接口使用独立计数，需配套新客户端才可准确参与此口径。

此次真机只读确认 `hello 1.5.1` 于设备时间 23:09:34 成功安装并产生 IP 仓库的排队记录。当时统计读取的 15 分钟门限到 23:24:14 才到期；其后再次核查，服务器 `hello` 已为 1、对应队列记录已删除，但设备缓存仍为 0。根因是“安装报告受读取冷却限制”和“先 GET 旧计数再 POST，确认后未更新快照”共同导致延迟，并非该次安装报告丢失。未手动清缓存、修改时钟、补造事件、改队列或重启真机。

本地正在实现 v2：设备侧持久随机种子，派生每仓库/应用匿名标识；服务器以应用 ID + 该标识去重，事件 token 仍负责请求重试和冲突检测。应用目录之外保存身份，因此普通卸载/重装/升级不会重生标识；恢复出厂或完整删除身份仍可能表现为新设备。匿名标识不证明真实硬件，不能用 IP、MAC、序列号作替代证明。

v2 将读取缓存（900秒）和报告请求门限分离；GUI 每30秒给待上报事件一次后台重试机会，安装成功后立即尝试启动，实际请求仍受持久最小间隔、失败退避和服务器 Retry-After 约束。服务端 ACK 同时返回该应用当前去重设备数，客户端严格验证 token/应用后直接更新显示，绝不猜测本地加一。当前序列23的界面文案为“安装次数 N次”，未知仍为 `--`。关闭界面期间不宣称有后台常驻报告服务。

## 本地 v2 客户端与界面接入

`c1pkg_device_metrics_record_install/start/poll/cancel` 已接入在线安装成功后的唯一 store 挂钩及 GUI。旧 v1 API 保留用于旧协议兼容与回归，新挂钩不同时写两种报告。CLI 在线安装也入同一持久队列；实际网络同步目前由打开的 GUI worker 执行，不声称闭合界面后有常驻服务。GUI 安装完成立即尝试启动，无任务时每30秒重新检查；GET 的900秒缓存与独立持久上报门限分开，失败按60/120/240/480/900秒退避，服务器更长 Retry-After 优先。

设备随机种子和初始化标记位于包管理私有状态的 `metrics/`，不在可卸载应用目录。HMAC-SHA256 输入采用版本域分隔和长度限定字段，普通仓库按精确规范化 base + app；仅四个明确官方 HTTP 地址（域名/IP × `/c1/v1`/`/c1/v2`）的**身份作用域**统一，避免同一官方仓库改前缀或别名重复计数。实际请求/队列/缓存来源仍按精确 base，不自动走另一个地址、不迁移异域旧事件、不合并 HTTPS 或自定义仓库。

新缓存独立保存并校验摘要，初始化后丢失/损坏不能归零请求门限。旧 v1 缓存仅首次导入其 retry_at（包括永久暂停），旧计数不会出现在 v2 快照。ACK 必须同时匹配 v2、token、应用和标准 uint64；直接保存服务器给出的当前 count，之后才移除事件。丢 ACK/掉电仍是同token同key安全重试。

GUI 列表在当前序列23使用 `N次`，详情使用“安装次数”/`Installs`；本地页隐藏统计，未知仍显示 `--`/“暂无统计”，不把未知当作零。底层按“累计接受过成功安装报告的去重本地身份”计数，卸载不减、同设备再次安装或升级不增；不是当前安装存量或经过硬件证明的物理设备数。

### 明确的准确性边界

- 这是匿名客户端自报数据。随机事件 ID 提供重试去重，不是防伪安装凭据；恶意客户端仍可能伪造事件。服务端必须校验包/版本并限流，不能把统计用于授权、验签或软件可信度判断。
- 安装事务与统计队列刻意解耦；成功提交后、入队之前掉电会漏报。队列满、锁竞争、随机源/存储异常也会漏报。恢复事务不补发，避免失败调用或重复恢复虚增。本实现选择允许漏报，而不是声称分布式「恰好一次」或破坏安装成功结果。
- 计数是服务端已接受的去重事件数。新服务端不可导入下载日志冒充安装数据，旧版本/离线安装不可估算补零。

## GUI API 契约（保留的 v1 接口参考；新 GUI 使用 device_metrics v2 API）

新增 `c1pkg_device_metrics_record_install/start/poll/cancel` 已用于新安装挂钩和 GUI；下面保留 `c1pkg_metrics_*` 说明以记录 v1 行为。新版网络合同分别为 `metrics.v2` 的 `C1PKG-METRICS 2`，以及 `install-events.v2` 的 `C1PKG-INSTALL 2`，事件字段在 v1 基础上附加64位小写十六进制的设备应用键；ACK 增加 `I<TAB>APP_ID<TAB>CURRENT_COUNT`，仅该服务器返回值可更新新界面的设备数量。

只需包含 `pkg/metrics.h`（包目录内可直接 `metrics.h`），不扩展 `c1pkg_package`，不更改签名索引。

1. GUI 保存一个初始化为零的 `struct c1pkg_metrics_snapshot` 和一个初始化为 NULL 的 `struct c1pkg_metrics_job *`。
2. 进入应用管理界面时可调用 `c1pkg_metrics_start(config)`。安装成功后和每 15 分钟可再次调用，但已有非 NULL job 时不要启动第二个。调用立即返回，不等待网络、磁盘锁或子进程完成。配置在 fork 时复制，不要求保留临时配置字符串。
3. 在现有 UI 定时器中调用 `c1pkg_metrics_poll(&job, &snapshot)`。返回 0 表示仍进行中；1 表示结束并有可用或不可用的 snapshot；-1 表示失败/取消并将 snapshot 清为空。结束时函数释放 job、置 NULL 并回收直接子进程。每次轮询均非阻塞。
4. 按行渲染时调用 `c1pkg_metrics_lookup(&snapshot, package_id, &count)`。返回 1 才可显示 `uint64_t count`，包括明确的 0；返回 0 显示「暂无统计」。缺失包 ID、旧服务端、无效响应均不是零。lookup 不访问文件和网络。
5. 离开页面调用 `c1pkg_metrics_cancel(job)`，随后继续在应用级定时器轮询，直到 job 变成 NULL。cancel 不阻塞；必须继续 poll，避免遗留僵尸进程。应用退出关闭结果管道后，后台请求仍有严格超时且不持有 GUI/设备锁。
6. GUI 不调用 `c1pkg_metrics_record_install`；store 已调用。网络失败不弹安装失败对话框，也不改变安装按钮、排序可信度或任何验签结果。

同一快照只属于启动该 job 时的仓库。仓库配置变化时先清除旧 snapshot，取消旧 job，等旧 job 回收后启动新 job，防止 GUI 显示其他仓库的数据。GUI 只展示当前经过签名索引认证的应用；统计响应中的额外 ID 不加入应用列表。

`metrics_start` 当前针对单线程主进程设计（使用 fork）；不要从多线程进程的任意线程调用。统计子进程关闭继承的所有非结果描述符，避免延长 framebuffer、输入、终端或包/应用锁的生命周期。

## 网络协议（v1 兼容协议，保持原契约）

仓库 base 去掉末尾 `/` 后，附加以下路径。仅支持 HTTP/HTTPS，不跟随重定向，不尝试 IP 别名，不读取 curl 配置或代理凭据。带凭据、查询、片段、百分号转义、异常点路径的 base 不用于统计，但这不影响包仓库原有行为。当前统计 URL 保守语法不支持 IPv6 字面量。

请求仅含固定 User-Agent `c1pkg-metrics/1`、HTTP 必要字段与下列正文；不发送设备序列号、永久设备 ID、Wi-Fi、输入内容、用户名、文件路径或用户配置。事件 ID 是每次成功安装独立生成的 128 位随机数，不关联同一设备的其他事件。HTTP 服务器和网络基础设施仍能看到连接源 IP；服务端应避免在事件日志中长期存储 IP、原始请求头或随机事件对应的用户信息。优先部署 HTTPS；HTTP 的统计只能作为可被网络篡改的展示数据。

### GET `<base>/metrics.v1`

只有 HTTP 200 且严格通过解析才表示协议可用。正文为 ASCII、LF 行尾、必须最后一个 LF，不允许 NUL、CR、空行、额外字段；上限 8192 字节。第一行固定 `C1PKG-METRICS 1`，随后 0–128 个记录，每条由以下三个 TAB 分隔字段组成：

- 固定标记 `I`。
- 应用 ID：1–32 字节，沿用 `c1pkg_safe_id` 的 ASCII 字母、数字、点、下划线、连字符规则，不得首尾为点或包含连续两个点。
- 已接受安装次数：标准十进制 `uint64_t`，范围 0–18446744073709551615，无正负号、空白或多余前导零。

记录必须按 ID 的 ASCII 字节序升序排列，ID 唯一。只有服务端明确跟踪的 ID 才出现；某 ID 明确为零时可传 `0`，不提供数据时省略该 ID。未知/未实现接口应返回 404 或 501，而不是伪造全零列表。

客户端先成功读取本接口才尝试 POST，因此旧服务端不会收到安装事件请求。网络故障、404、异常响应将快照标记不可用。成功的统计可能有短暂延迟：本轮先读快照再发送事件，不会猜测 POST 重试是否首次计入、不会自行加一；新计数在后续同步读取。

### POST `<base>/install-events.v1`

Content-Type 为 `text/plain`。正文第一行固定 `C1PKG-INSTALL 1`；第二行包含 TAB 分隔的四字段：固定标记 `E`、32 个小写十六进制字符的事件 ID、包 ID、版本。第二行之后恰好一个 LF。版本 1–48 字节，沿用 `c1pkg_safe_version`（ID 字符加 `+`，同样限制点），整个事件正文最多 256 字节。URL、设备 ID、时间戳和安装路径不在正文中。

服务端只有在数据库事务持久提交之后才能返回 HTTP 200。确认正文第一行固定 `C1PKG-INSTALL-ACK 1`；第二行为 `E`、TAB、原样事件 ID、LF。新事件与内容完全相同的重试都返回相同 ACK。客户端仅接受 HTTP 200 加匹配的完整 ACK；任意 HTML、错误 token、成功状态但无 ACK、响应丢失或其他状态都保留原事件 ID重试。

### 服务端事务与限制

- 请求体硬上限 256 字节，先做长度/语法/路径/Content-Type 校验，禁止未知字段、控制字节、重复记录。HTTP 服务本身还要有请求头上限、读/写超时、并发限制。
- 安装事件只能引用该仓库真实发布过的合法包/版本。旧客户端离线队列可能上报历史版本，因此不要仅因该版本不在当前索引就丢弃；可用服务器自己的发布历史进行校验。统计数据库不是签名索引的一部分，不改签名、序列或发布内容。
- 以 `(repository_id, event_id)` 为唯一键，在同一个持久数据库事务中插入事件及更新该包计数。首次插入才 `+1`；已有且包/版本相同则不更新；已有但内容不同则返回 409，绝不能再计数。计数到 `UINT64_MAX` 时拒绝新事件，不能溢出或归零。
- 服务端随机 token 去重记录须持续保留；当前客户端队列没有时间期限。若服务端清理去重键再接受旧 ID，会破坏幂等。可设置数据库总容量上限，到限额时返回 503，不能悄悄淘汰去重键。未来需要有限去重期限时必须升级协议，使过期事件不可再被计数。
- 给 POST 设置按来源及全局速率/并发/存储配额，给 GET 设置缓存和速率限制；返回 429/503 与数字 `Retry-After`。具体阈值须结合真实服务端容量配置，不能从既有下载并发限制臆造每分钟请求额度。
- 持久事务失败不能 ACK；ACK 丢失后重试使用原事件 ID。数据库备份/恢复必须同时涵盖事件去重表与计数表，不能只恢复其中之一。
- 必测：首次事件加一、同 ID 同内容并发和重试只加一、同 ID 不同内容冲突、非法/过长/未知包事件拒绝、超额限流、计数溢出、数据库故障/重启后幂等、下载请求完全不触碰计数。

## 设备端有界队列与重试

- 状态独立位于 `C1PKG_STATE_ROOT/metrics/`，目录 0700、文件 0600，私有普通文件须只有一个硬链接。拒绝符号链接、非普通文件和错误所有者/权限。网络事件中不发送此路径。
- 全局最多 64 个事件，每条磁盘内容最多 1280 字节（仓库 URL + 协议正文），总事件数据最多 80 KiB；实际默认 URL 下远小于上限。缓存固定大小约 8 KiB，响应内存硬上限 16 KiB。单次目录扫描最多 128 项。
- 入队使用独立非阻塞 queue 锁，有限本地写入、fsync 与原子 rename；不等待统计网络，不持有包安装锁。队列满或锁忙时丢弃新统计，不删除既有事件，不影响安装成功。文件系统自身的 I/O 延迟不属于网络超时保证。
- 事件文件绑定入队时的规范化仓库 base；切换仓库不会将旧事件发送到新仓库。回到旧仓库后可重试。事件没有设备级固定标识。
- 每次后台同步最多 1 次 GET + 4 次 POST，无内部网络重试。每次请求连接超时 2 秒、curl 总超时 4 秒、客户端监管上限 6 秒；输出通过有界管道读取。拒绝超长响应，杀掉并回收 curl 子进程。
- 跨进程非阻塞 worker 锁防止同时同步；联网前先持久写入至少 15 分钟冷却。重启不会清除冷却，切换仓库也不能绕过冷却。GUI 定时器只负责触发，冷却内不会联网。
- 数字 `Retry-After` 延长冷却（取最长且溢出饱和），成功响应也遵守，收到后停止本轮后续请求。v1 合同要求数字秒数；HTTP 日期、无效/超长字段保守地暂停自动统计重试，避免猜测日期而提前发送。恢复需在停用统计任务后移除本地 `metrics/cache`，不动事件文件；此恢复步骤不得用来绕过仍有效的服务端限制。
- 只有匹配 ACK 才删除事件。ACK 丢失、队列删除失败、断电都会保留同一 token；幂等由服务端唯一键保证。腐坏事件不会上报；它占用队列配额，可由本地维护清理，不能伪造成新 ID重发。
- 统计缓存只在同一仓库且正常 15 分钟冷却内复用；签名索引缓存、最高序列、安装指针、事务日志与统计完全独立。
