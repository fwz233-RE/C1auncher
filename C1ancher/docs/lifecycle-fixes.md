# 生命周期修复说明（本地，2026-09-06）

本轮修改保留原有未提交工作，不调整主页、阅读器或音乐界面的视觉布局。产物统一写入 `build/lifecycle-fixes`，不覆盖此前签名发布产物；尚未部署到服务器或设备，未执行生产签名、设备维护、重启或稳定通道推广。

## 已实现的行为

1. 所有应用持有可继承的运行锁，只有直接使用硬件的应用另持有硬件独占锁。终端模式可以由主页正常绘制。新签名包可显式声明 `terminal` / `direct`；旧包保持原有兼容规则。
2. 包安装和回滚使用私有、持久化事务记录：先同步已验证内容，再记录目标 inode 和旧指针，最后切换指针。启动、列表及后续操作先恢复未完成事务；可疑记录安全拒绝。回滚后重装保留的新版本会重新下载、验摘要并逐文件比较，而不是仅凭目录名信任它。
3. 当前 updater 损坏不会阻止尝试备用槽；普通异常退出有重试次数上限，bootstrap 保留父进程身份，统一处理致命、切槽和临时错误。
4. 恢复 generation 之前由只读根中的固定验证器验证签名、组件和元数据，再执行已校验 inode，避免候选程序自行证明可信。固定验证器只能通过可信 enrollment/maintenance 安装。
5. 核心更新锁忙作为可重试状态处理，不删除锁、不据此切槽或回滚；等待覆盖长时间下载，并可响应停止。
6. 主页主循环经匿名管道每约两秒发送心跳。启动器检查启动宽限和运行超时；核心确认同时要求摘要匹配的 ready 及同一主页 PID 跨过完整 30 秒窗口的新心跳。健康探测在总期限内重试。
7. 终端会话和启动器采用 Linux 子进程收养机制，逐代回收本会话后代。shell 先退出、忽略 HUP、独立进程组和后代继承锁均有隔离回归；不按全系统名称杀进程。
8. 卸载、恢复和清理不再要求安装用的 4 MiB 空间预留。历史版本清理持有运行锁；有应用运行时保留全部版本，空闲时保留 current/previous，不删除旁边的用户数据。
9. APP 和更新界面使用独立终端会话，不向忙碌的用户 shell 注入命令；普通终端及其输出单独保存，退出包管理器返回主页。
10. 批量更新区分成功、跳过、单包失败、取消和存储故障。单包失败后继续，取消或存储故障停止；命令行不把“跳过”报告为“已安装”。
11. 最低 bootstrap/updater 能力版本在准备、激活、开机及恢复时强制检查；可信 bootstrap 版本记录绑定根脚本摘要，旧版本兼容回滚保留。
12. 待确认核心按真实 boot ID 和候选摘要持久化尝试次数；同次开机重复 reconcile 不多计，最多允许三个不同开机周期，第四次启动前回滚，确认或回滚后清理记录。

## 下载优化与兼容边界

应用归档支持单次调用内的断点续传，严格验证 `Content-Range`，保持精确大小上限，最终仍验证整个包的签名索引摘要。服务器忽略 Range 或返回 416 时丢弃临时前缀重下，不拼接成错误包；取消、本地写入故障和超限不会被 IP 回退掩盖。响应头受 64 KiB 限制。

续传不跨程序重启，也不跨备用服务器保留前缀。每端点最多四次下载尝试，每次最多 600 秒，服务器忙等待每次最多 30 秒、最多三次；不是整项操作共用 600 秒。索引和签名共享 45 秒期限，不续传。提示区分检查仓库、下载和续传。

地址保持域名优先的普通 HTTP：`http://www.fwz233.com` → `http://123.56.214.77`。自定义仓库不被替换。生产设备和服务器升级前应省略发布工具的新 `-mode` 参数；此前发出的 Windows 发布 ZIP 未替换。

## 运行期日志

固定可信 helper 新增日志收集入口，在运行期间按精确字节边界轮转 `supervisor.log`：每份最多 64 KiB，保留当前文件及四份历史，总日志内容最多 320 KiB。超长无换行输出也受限制，不靠重启才轮转，不用直接截断服务仍持有的日志描述符。

日志目录不安全、只读、消失或写满时停止保存，但继续排空管道，避免日志故障卡住核心服务。包装层保留真实退出码并转发停止信号，有界清理自己的后代；固定 helper 不支持日志入口时退回原启动路径，不重启已运行过的命令。正常空闲只使用低频等待，短周期检查限于停止清理阶段。

## 验证入口

- `make BUILD_DIR=build/lifecycle-fixes all`：构建四个 MIPS 核心程序并输出 ABI 报告。
- `make BUILD_DIR=build/lifecycle-fixes lifecycle-test`：主机 C 测试、终端/UI 生命周期、启动器进程、bootstrap、可信恢复、核心 HTTP 和应用 HTTP 测试。
- `powershell -NoProfile -File tests/test_enrollment_host.ps1`：只加载验证函数，验证维护包公钥绑定，不执行安装器或 ADB。
- 服务器目录运行 `go test ./...`、`go vet ./...`，Linux 下运行 `go test -race ./...`。
- 服务器目录以隔离 Linux/WSL root 运行 `python3 tests/test_device_integration.py`，使用一次性测试密钥和临时存储，验证真实 Go 发布工具到 C 包安装、模式保存、回滚再升级和旧版本回收。默认取本轮 MIPS 构建作测试 payload，不连接设备。

## 本轮验证结果

统一命令 `make -s -j4 BUILD_DIR=build/lifecycle-fixes all lifecycle-test` 退出码为 0。全部主机 C 测试通过；启动器进程 11 项、bootstrap 12 项、可信恢复 9 项、运行期日志套件 39 项、核心 HTTP 23 项和应用 HTTP 17 项均通过。日志套件包含部分 bootstrap 回归，数量不应作为互不重复的总测试数累加。

四个核心产物均确认 ELF32、小端、MIPS32r2/o32、hard-float double，且没有动态链接段。包事务另外通过 AddressSanitizer 和 UndefinedBehaviorSanitizer 检查。服务器 Go 测试、静态检查及 Linux 竞态检测通过；真实 Go→C 本地端到端测试通过。Windows 六项公钥验证检查通过，过程中未执行安装器或 ADB。

故障测试会有意输出 HTTP 403/429/503、超时和取消信息；以测试断言及最终退出码判断结果，而不是把这些注入错误视为生产故障。

## 发布前仍需完成

旧 bootstrap 的修复需要单独授权的可信维护操作，普通四组件核心包不能自动改写根文件系统。维护前必须备份；维护脚本、公钥保持和只读根恢复需要真机验收。物理断电、冷启动、休眠唤醒、真实显示输入交接及目标设备长期运行也仍需验收。当前本地构建沿用开发版本标识，不可直接当作新的不可变生产发行上传。
