# 电源键长按关机修复（2026-09-06）

## 行为

- 主界面运行时，同时识别 `KEY_WAKEUP`（143，项目硬件记录中的实体电源键）和 `KEY_POWER`（116）。
- 收到按下后计时约 3000ms，由 poll 超时驱动，不依赖自动重复或松手。触发前用 `EVIOCGKEY` 确认按键仍按下；UI 忙碌时可能晚于三秒处理。
- 短按在松手时转交原有短按路径：桌面锁屏、锁屏解锁，其他页面保留原有用途。长按不会先执行短按。
- 按住期间暂缓自动锁屏、休眠和已准备更新的切换。一次按住最多请求一次关机。
- 休眠唤醒产生的按键事件沿用原有过滤规则：先松开，再重新按住才能关机。
- 输入溢出、应用控制权切换会清除计时；积压释放事件不会触发关机。内核按键状态查询失败时取消本次手势。

## 系统关机

调用 `/sbin/poweroff`；仅在无法执行时依次尝试 `/bin/poweroff`、`/sbin/shutdown -h now`。不使用 `-f`、直接 reboot 系统调用或其他绕过正常关机流程的方式。

父进程检查命令退出状态，记录 `shutdown-requested`、`shutdown-command-completed` 或 `shutdown-failed`，等待期间继续向启动器发送存活信号。命令等待上限为十秒；超时仅终止本次辅助进程组，后续非阻塞回收，避免 UI 永久卡在 waitpid。失败后保持主界面运行，松手再按可重试。命令退出成功仅说明关机请求已被命令接受，不证明硬件已经断电。

只读检查当时连接的开发设备（序列号不公开）：PID 1 为 `/bin/busybox`，`/sbin/poweroff` 指向 BusyBox，`/etc/inittab` 配置了 `rcK`、卸载文件系统及 swapoff。没有执行任何实机关机命令。

## 测试与构建

新增三个硬件无关测试：

- `tests/test_power_key.c`：三秒边界、单次触发、短按、重复事件、输入来源、重置、唤醒过滤。
- `tests/test_power_runtime.c`：调用 UI 实际的输入/计时函数，以模拟 ioctl 验证两种键码、poll 截止时间、内核已松手、查询失败、积压释放和唤醒。
- `tests/test_poweroff.c`：仅运行 true、false、不存在的路径及测试自己创建的 sleep 脚本，验证退出状态、回退、超时、存活回调和超时后回收重试；不调用生产关机入口。

## 验证边界

本修复依赖主界面能够收到电源键按下事件。独占输入设备（EVIOCGRAB）的应用可能屏蔽该事件，因此尚不保证在所有第三方应用中全局可用。安装后仍需用户确认进行实体按键及实际断电验证；建议先保存数据、回到桌面，短按确认锁屏/解锁，再按住约三秒检查是否完成系统关机。墨水屏断电后可能保留画面，不能仅凭画面判断关机。
