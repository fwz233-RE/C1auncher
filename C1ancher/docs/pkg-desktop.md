# 应用包桌面 GUI 实现与验证（2026-09-20）

用户操作说明见 [pkg-gui.md](pkg-gui.md)。这次将旧的限时 ASCII 定位替换为显式、持久的 UTF-8 搜索筛选，并将全部仓库刷新移出键盘/绘图线程；不改变包签名格式、安装事务、公共输入法协议。

## 修改范围

- `src/pkg/gui.c`：统一顶栏、页面布局、双语文案、搜索编辑/结果状态、正常方向导航、确认运行/安装、逐层返回、后台结果接入。
- `src/pkg/gui_locale.h`：只读公共语言及 `utc_offset_minutes` 配置，默认 UTC+8；有界电量采集，不链接桌面 canvas。
- `src/pkg/gui_refresh.h`：新私有 header-only 子进程刷新器。初始已验签缓存和最终结果共用匿名结果管道；真实进度使用独立非阻塞管道，取消用第三根管道的 EOF/HUP。
- `tests/test_pkg_gui.c`：实际生产渲染器、输入解码与分发路径；仓库边界可延迟，刷新本身真实 fork/pipe。
- `tests/test_pkg_ime.c`：保留公共 SDK 的真实 Unix 套接字测试，更新为持久筛选语义。
- `tests/test_pkg_refresh.c`：新增真实 repo.c/Ed25519/curl/缓存锁的子进程集成测试；只用本机回环 HTTP 服务器。
- `tests/test_pkg_desktop.py`：独立编译上述测试，额外验证时区/语言/电量，生成原生及三倍像素预览。

顶栏使用 `ui/chrome.h`，显示选中应用名（空列表回退为“应用”/“Apps”），与桌面共用绘制函数。安装统计已通过 `metrics.h/c` 的独立异步任务接入主循环和应用详情；明确区分未知、零和 64 位计数，不参与安装可信度判断。统计含义及服务端待接入状态见 [安装统计协议](pkg-metrics.md)。

## 状态和安全约束

1. 列表本地为页 0、商店为页 1。两页使用白底黑字标签和 1px 选中下划线，Shift 管理及统计列标题融入同一行；实际状态统一放入页脚，普通列表显示五行，搜索筛选四行、输入法可见时两行。本地确认直接打开，商店确认进入管理，两页单按 Shift 均可进入管理。筛选字段独立于选择位置，方向键仅改变结果选择；浏览字母仍用于名称/ID 定位，有限中文首字母表和 1.5 秒重复循环不变，`M` 不承担管理操作。内部服务包 `c1-ime` 不进入用户可见列表。
2. GUI 将桌面限定转发的 `ESC[57441u` 解码为单按 Shift 管理事件；Shift 组合键不会在释放时补发管理。原 `0x09` 字节和 `/` 保留为兼容搜索入口，但不再显示“表情搜索”或声称实体表情键已验证。`Shift+Space` 继续复用公共输入法。搜索中的确认先结束输入焦点，单按 Shift 保留搜索，再次确认才打开本地应用或商店管理。
3. 字段内无匹配时 `count=0`，不存在“保持旧项目但屏幕写无匹配”的危险状态。非法/过长 IME commit 保留原搜索、显示错误并丢弃未消费确认与后续排队键；新的 Enter 不能清除错误后启动旧选择。
4. 仓库 API 只在刷新子进程执行；父进程从未在主循环同步等待网络或读取/验签缓存。最多一个 worker，重复刷新请求合并。
5. 初始缓存仅供浏览。完整新结果须通过原签名、防回滚及缓存提交，再由父进程验证管道完整性和指定子进程的成功退出，才能将当前列表标记为可安装。任何失败不覆盖最后已验签目录。
6. 完成刷新使用稳定 ID 恢复两页选中项，避免增删/重排造成误选。等待期间无阻塞导航或隐含安装队列；安装要求刷新完成后新的显式确认。
7. 刷新与安装不并行；取消仅关闭刷新控制 fd，不更改父进程的安装回调，也不向父进程组发信号。worker 让 repo/util 原有取消流程回收 curl 子进程并在 `repo.lock` 内清理自己的临时文件；父进程不删除共享缓存临时路径。
8. 本地列表与商店独立。完全断网、没有可验签缓存、刷新失败均不能隐藏本地应用；存储报错保留最近本地快照但禁止实际运行或修改。

## 完整整合测试

以下为搜索/异步刷新实现的完整整合命令和覆盖范围。在 WSL Ubuntu-22.04、`C1ancher` 目录运行：

- `make -j4 BUILD_DIR=build/pkg-search-20260919 pkg-gui-test pkg-ime-test build/pkg-search-20260919/host-c1pkg build/pkg-search-20260919/c1pkg`
- `python3 tests/test_pkg_desktop.py --output-dir build/pkg-search-20260919/previews`
- `python3 tests/test_pkg_desktop.py --sanitize --output-dir build/pkg-search-20260919/previews`

覆盖内容：

- 顶栏仅两段文字（选中应用名和时间/电量）、页面内容 y>=18、五行/搜索四行/输入法两行、所有文字像素预算、UTF-8 省略和各区域不重叠。浅底标签与细下划线的实际像素、两标签黑字、Shift 图形提示、统计表头和页脚状态均有断言。
- 语言环境优先级、CRLF/注释/超长行、防长行尾部伪造配置；正负与跨日时区不受进程 `TZ` 干扰；合法电量与未知状态。
- 真实按键字节进入生产解码器：在 800ms 模拟网络等待内完成连续五次向下滚动、左右切页及选择保留，要求导航在 250ms 内结束且 worker 仍在运行。
- 兼容字节打开搜索、中英混排名称、名称/ID 子串、空格文字、完整 Unicode 退格、任意长空闲保持、确认不误启动、零匹配、防误执行和逐层返回。搜索编辑时单按 Shift 不打开管理。
- 从生产列表分发器进入 Shift 管理，而不是直接调用管理函数：覆盖本地直接打开、商店进入管理、选择安装/更新、卸载双确认、取消、空列表和离线管理。
- 20 次刷新请求只产生同一任务；16 次立即取消 fd 数稳定；继承的高位描述符在 worker 内关闭；子进程崩溃/不完整结果不可授权；刷新重排按 ID 保留选择。
- 正在刷新时本地应用确认可运行，先取消并回收刷新任务；无关子进程仍存活，不受刷新清理信号影响。
- 普通详情、更新和卸载的安全默认值、双重确认、存储错误、完全离线、本地列表保存、缓存不能自动授权安装。
- 真实公共 IME SDK 的 STATUS/MODE 顺序、UTF-8 commit、键顺序、非消费回退、5 秒超时、断线、队列满、错误响应/序号、超长或截断 commit 均不误执行。
- 真实签名仓库集成：真实 curl 被阻塞时，竞争刷新被实际 `repo.lock` 拒绝；合作取消在测试要求的 750ms 内完成，curl 及 worker 均已回收，缓存保留，临时文件清理。后继刷新可提交，签名错误和序列回滚均不产生可安装记录。

`--sanitize` 对 GUI、IME、刷新器和仓库胶合代码启用 AddressSanitizer/UndefinedBehaviorSanitizer。首次全量检查发现既有 `third_party/ed25519/{fe,ge,sc}.c` 的有符号左移 UBSan 告警，本任务未越界修改密码学源码；脚本明确打印这一限制，第三方 Ed25519 对象只启用 AddressSanitizer，其余代码继续启用两种检查。不得将该运行概括为“所有第三方代码 UBSan 无问题”。

主机测试的 `launch failed: No such file or directory` 是故意拦截 `execl` 后返回 ENOENT 的预期诊断，不是访问真实设备失败。PBM/PNG 来自生产渲染器和测试元数据，不是设备实拍。

## 集成建议与边界

- 刷新与语言模块为私有头文件；安装统计模块 `src/pkg/metrics.c` 已加入 Makefile 的设备端、主机程序和 GUI/IME 测试链接。`test_pkg_refresh.c` 的真实缓存锁集成由 `test_pkg_desktop.py` 运行；统计协议与事务挂钩测试已加入 `host-test`。
- `repo.c` 已将服务器冷却持久化并按仓库隔离，刷新子进程、父进程安装和重开 GUI 共享同一截止时间。GUI 初始化及安装前调用纯字符串 `c1pkg_repo_bind_transport` 绑定仓库，主线程不增加 I/O 或网络等待。未完成请求按一次性 60 秒策略恢复，已知更长的 Retry-After 不缩短；损坏及真正溢出独立报错。详情与回归见 [下载传输](package-transport.md)。
- 退出采用合作取消而不是强杀缓存写入者。真实网络阻塞已验证快速取消；不可中断的内核文件 I/O 仍可能延长退出，不保证所有硬件故障下的绝对时限。
- 本次验证不等同于实机物理表情键、墨水屏残影/刷新、真实 Rime 服务词库、设备存储和实际安装包验收；没有部署、提交或推送。
