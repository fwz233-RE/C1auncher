# Refresh Test — 屏幕刷新测试

独立应用，ID `refresh-test`，版本 `0.1.1`。适用于 C1-Slim 的 296×152 单色墨水屏。安装后直接运行，无须素材、字体或额外依赖，不替换 Bad Apple。

用途：结合手机原始录像和程序 CSV 日志，区分软件提交速度、屏幕实际可辨认的新画面、过渡和残影。**应用本身无法测出物理显示帧率，屏幕上的 WAIT 表示软件等待时间。**

## 全键盘操作

启动默认 MOVE 图案、700ms 提交后等待。进入新测试段时全刷一次，再保持 2 秒，随后开始运动。

- 直接按字母键调速：`Q`：1000ms；`W`：700ms；`E`：500ms；`R`：300ms；`T`：200ms；`Y`：100ms。无须数字键、组合键或回车。常用三档依次按 **W、E、R**，每档观察或录制 20～30 秒。
- `0.1.1` 修正了旧版要求数字键的问题：**Q 现在调速，X 退出；R 现在调速，C 全刷清理**。外接键盘数字 1～6 仍可作为可选别名。
- 右方向键或 `+` / `=`：等待时间减少 50ms，提交更快。
- 左方向键或 `-`：等待时间增加 50ms，提交更慢。
- 范围固定为 100～2000ms；只响应按下，不使用长按自动连发。
- `M` / Tab：依次切换 MOVE、FLIP、SCENE。
- 空格 / Enter / OK / `P`：暂停或继续。继续时新建测试段并全刷清理。
- `C`：新建测试段并全刷，保持当前暂停状态。
- `H`：帮助，自动暂停；关闭帮助后仍保持暂停，再按空格继续。
- `X` / Esc / 返回 / HOME：退出，关闭并保存日志，恢复原快刷设置。
- 电源键留给系统。休眠期间的数据不宜用于同一组测量，唤醒后按 C 开新测试段。

切换速度或图案会开启新的测试段 S，执行一次全刷和 2 秒保持；如果原本暂停，则仍暂停。请逐档测试，每档录 20～30 秒，避免连按切换导致连续全刷。

**FLIP 为高对比黑白交替，可能引起不适；有光敏性风险者请跳过此图案，出现不适立即暂停或退出。** 100ms 档仅用于短时对比，不保证达到 10 个可见新画面/秒，也不宣称长期运行效果或面板寿命已经验证。默认 30 分钟自动退出。

## 三种图案

- MOVE：黑色矩形在白底上往返，单个周期 4 秒，以真实时间定位，便于观察运动位置和残影。
- FLIP：中间 250×60 区域按尝试提交的帧编号奇偶交替黑白。忙碌拒绝也消耗编号，因此连续被接受的帧可能同色，这是丢失提交的证据，不要按颜色切换数直接推算提交次数。
- SCENE：原创多个运动圆形组合，按实际时间生成，提供比单块切换更复杂的内容。不依赖低帧率视频素材。

帧始终是设备原始 1bit 数据，每帧 5624 字节。没有现场视频解码、媒体解压或下载；也没有整帧去重，每次尝试都有新编号。

## 屏幕信息和录像

- `WAIT n MS`：上次绘制调用和日志处理之后，再等待的时间；处理耗时会增加实际间隔。
- `Sxxxx`：测试段编号。速度/图案改变、继续播放或 C 清理会递增。
- `Fxxxxxxxx`：整个会话中每次绘制尝试的编号，包含全刷、帮助/暂停页和失败的提交。帮助页不显示编号，但日志仍保留；只分析 `kind=sample` 的正常测试帧。
- `Txxxxxx MS`：当前测试段的场景时间，渲染取样时记录。全刷/界面页为 0。
- 画面中间两排编码：24 位帧编号（低 24 位），从左到右为高位到低位；每列上排黑表示 1，下排为反码。两排同列同黑或同白可能是过渡、残影或拍摄问题，不能强行判成稳定帧。超过 16777215 次提交编码重复，完整编号仍在 CSV；正常限时会话远低于这个数量。
- 两侧保留固定黑、白参考区域，中间运动区域不占用编号栏。屏幕编号栏本身也会增加刷新负载，测试结果代表这一测试布局。
- `LOG OK`：日志正常；`TMP LOG`：正在使用易丢失的临时目录；`NO LOG`：无法记录或写入中途失败，录像仍可用，但缺少完整软件时序。

建议手机固定、镜头正对全屏、锁定对焦曝光、使用无频闪光照。优先 120/240fps，至少 60fps。录像应包含每段的全刷与 SETTLE 画面，以及后续 20～30 秒运动。保留原始视频，不进行慢动作转码或聊天压缩，并说明实际拍摄帧率和播放帧率。

先比较 MOVE 的 700/500/300ms，再考虑 200/100ms；FLIP 和 SCENE 分别重复。2 秒保持只是试验流程约定，**并非来自驱动的显示完成信号**；录像若显示仍未稳定，分析时继续排除过渡部分。

## 日志位置与含义

自动在设备 `/storage/mtp/RefreshTest/` 创建独立 `refresh-日期-随机值.csv`，不会覆盖以前的会话。正常退出后，通过设备文件传输功能复制整个 `RefreshTest` 文件夹到电脑，与原始录像一起提供即可。

若主目录不可写，尝试 `/tmp/RefreshTest/`，屏幕显示 TMP LOG；该目录可能在重启后丢失，需要在重启前通过已有的设备连接取出。两个目录均失败时显示 NO LOG。显式 `--log-dir` 失败不会静默换目录。

CSV 字段：

- `kind`：session / segment / ready / key / full / ui / sample / exit / open-error。
- `id`、`segment`、`pattern`、`wait_ms`：尝试编号、测试段、图案和等待参数；事件行编号为 0。
- `start_us`、`end_us`：相对会话启动的单调时间，分别在绘制调用前后采样，单位微秒。差值含设备适配层控制与写入耗时，不是屏幕完成时间。
- `scene_us`：生成画面时的场景时间；渲染发生在 start_us 之前。
- `full`：是否请求全刷。
- `status`：accepted 仅代表绘制调用没有返回错误；busy 代表 EAGAIN/EBUSY；error 为其他失败；event 为操作记录。
- `detail`：会话版本、UTC 起点、操作或错误信息。

每秒和状态变化时刷新用户态日志缓冲，正常退出时同步文件。突然断电/进程被杀可能丢失末尾记录。同步文件写入可能影响实际提交间隔，所以应以日志 start_us 实际间隔为准。样本 busy 不立即重试，按正常间隔发下一个编号；全刷或界面页 busy 每 250ms 重试一次，最多 8 次。其他设备错误退出并记录。

画面运动按实际时间生成，定时器在一次调用与日志处理完成后重置，没有排队补帧。在本驱动/波形和当时温度下，提高提交速度是否增加可辨认画面，需要靠录像判断；驱动即使返回成功也可能合并或忽略更新。

## 开发与验证

在电脑 `App/refresh-test` 目录运行：

    go test ./...
    go vet ./...
    go run . --preview preview.png --pattern scene
    .\build.ps1 -Version 0.1.1

默认输出为仓库根 `build/refresh-test-publish-0.1.1-20260909/payload/refresh-test`。构建脚本进行主机测试/vet、Linux MIPS 小端硬浮点静态交叉编译及 vet、ELF 校验，附带许可证和本说明，不包含令牌。

可选设备参数：`--interval 500ms --pattern move --duration 5m --log-dir /storage/mtp/RefreshTest`。`--duration` 为 1 秒～1 小时。主机 `--preview` 和 `--version` 不打开硬件、不创建会话日志。

此版本不修改驱动、自定义波形或 refresh_max，沿用本仓库 Bad Apple 已使用的设备显示锁、输入和快刷接口。主机测试与软件 PNG 预览不等于真机测试，真实效果和忙碌行为需要现场验收。
