# C1-Slim 发布器与应用仓库服务源码

本目录公开 `c1publish` 发布器及其共用的 Go 仓库实现，方便复现发布工具。部署凭据、服务器实际配置、私钥和旧运维脚本不在公开范围内。第一方代码遵循根目录 LICENSE；第三方声明见 `../tools/publisher/THIRD_PARTY_NOTICES.txt`。

## 构建和测试

需要 Go 1.24 或更新版本，无外部 Go 模块依赖：

    go test ./...
    go vet ./...
    go build -o c1publish.exe ./cmd/c1publish

Windows 发布器无参数启动时提供中文控制台菜单；完整使用说明见 `../docs/publishing.md`。完整跨平台发行包的构建脚本是 `../tools/publisher/build_self_service.py`，包内保留可信的公开配置和验签公钥。

## 自助注册与应用所有权

服务器配置 `selfRegistration: true` 时，`POST /api/v1/publishers/register` 接受作者名及由客户端安全随机生成的令牌。客户端先持久保存令牌，再发送注册请求；相同作者和令牌可重试。服务器只保存令牌 SHA-256 哈希。作者名唯一但不代表真实身份核验。

已认证作者首次成功发布未占用、未分配的新应用 ID 时，所有权与签名目录原子保存；之后只有对应作者可更新。已有配置作者的令牌同样可发布自己的新 ID，不需要逐个申请。既有受保护应用、已发布匿名应用和核心保留 ID 不能被新作者认领。旧静态令牌从配置移除后不会在注册表中继续生效。

`publishMode: open` 仍允许显式匿名 `-open` 发布；匿名应用没有独占所有权，其他人也可升版本。推荐需要作者名与独占更新权限的开发者使用注册后令牌发布。

服务器重启会验证注册表签名及其与目录的一致性。升级前必须停写并备份可执行程序、配置及完整仓库；旧服务程序不认识新增的注册表字段，启用注册并接受写入后不能直接用旧程序回滚，也不能将旧目录序列覆盖回去。发生问题应停写并向前修复，保留新增作者和应用历史。

## 配置示例

以下都是占位值，必须使用维护者自己的可信密钥；服务器监听环回地址，由反向代理提供外部访问。代理必须转发注册和发布两个 POST 路径。

    {
      "root": "/var/lib/c1repo",
      "listen": "127.0.0.1:8091",
      "publicKey": "/etc/c1repo/app-public.raw",
      "signingKey": "/etc/c1repo/app-signing.pem",
      "selfRegistration": true,
      "publishMode": "open",
      "publishers": [],
      "downloads": 2,
      "queue": 20,
      "bytesPerSecond": 300000,
      "maxRepositoryBytes": 2147483648
    }

自助注册有全局速率限制和作者总量上限，但没有邮件验证、实名核验、令牌找回或账号自动恢复。开发者应私下备份令牌。公开服务仍需关注名称抢占、注册滥用和存储容量；开放注册不等于无限资源。

建议用 HTTPS 保护注册和上传。兼容既有 HTTP 服务时需要客户端显式确认风险；验签公钥不能阻止 HTTP 上传令牌被窃取。设备程序仍需提前交叉编译为静态 MIPS 设备应用；发布器本身不提供应用开发环境。
