# Pinao — 掌上音乐工作台

## 0.1.10 逐格延音（已发布服务器）

- 逐格录制时，按住旋律键并向右移动一格，延长该音到下一格；多个持键分别延长，鼓声不延长。松键后再移动不写入新音，也不清空已有内容。
- 向左只导航，不写延音；页内第16格右移仍回到第1格，不跨首尾连音。跨页时，在第16格持键，短按 O 到已有下一页，或长按 O 新建下一页，可连接到下一页第1格。
- 延音格之间用黑色横线连接；跨页延音在进度条两端显示短线。一个连接表示至少一个音延续，选中格上方显示该格的音符。
- 保留目标格已有的独立同音起音，不自动合并；每格仍最多8个事件，满格不覆盖。松开再按同一个音会重新起音。Delete 清空当前格，后续失去前接音的延音改为独立起音，不删除其他格。
- 自动播放与 WAV 导出共用延音处理；连音不在每格重新敲击。从延音中途开始或卡顿跳格后从当前格重新起音，停止/退出照常停音。自然衰减仍保留，延音不等于恒定响度。
- 工程仅在首次加入延音时升级为 format 3；旧 format 1/2 工程可正常读取。首次覆盖旧工程前保存 `song.json.pre-ties-<SHA256>.json` 原文件备份，备份失败则不覆盖。旧应用不能读取 format 3，回退需先另存新工程再恢复备份。
- 未改动 Enter/自动保存触发时机、音色算法、BPM、音量、导出目录或其他应用。测试范围及本地构建见 [延音发布说明](docs/ties-0.1.10.md)。

作者：**fwz233**。当前已发布版本：**0.1.10**。用于 C1-Slim 的 296×152 黑白电子纸屏和实体字母键盘。

本目录包含源码、构建脚本和测试；公开发布流程见仓库统一开发文档。应用 ID 是 `pinao`，显示名称为 **Pinao**，通过现有 HTTP 签名应用仓库分发。当前服务器已发布版本为 **0.1.10**，包含逐格延音。没有改动图书、音乐播放器或启动器的视觉布局，也没有为此替换系统核心。

## 0.1.7 删除与重新录入

- 普通模式下连续按两次 Delete 会清空整个工程，并将多页工程恢复为 1 个空页面；仍保留两秒内二次确认，避免误删。
- 逐格模式下按一次 Delete 只清空当前光标所在单元格，其他格子和页面保持不变，清空后可以立即重新输入琴音或鼓声。
- 清空整个工程会回到第 1 页并停止播放和录制；清空单元格不会移动光标，也不会退出逐格录制。

## 0.1.6 多页编曲（已发布服务器）

改动前的 0.1.5 源码已提交并推送到 GitHub，回撤点为 `dd281e121ce43c4019b95fae56cd949774d9d920`。以下按键和范围说明对应当前多页源码，不代表应用仓库已经更新。

- 主界面的琴键、鼓声、16 格进度及原有文字区域布局不变，只在右上角空白处增加页码：当前页白底黑字、大尺寸，相邻页白色细边、小尺寸。最多显示三页；首尾隐藏不存在的邻页，默认仅显示第 1 页。帮助页补充 I/O 操作。
- 默认一个八拍／16 格页面。短按 I/O 切换已有的上一页／下一页；长按约 0.7 秒，在当前页左边／右边插入一个空白页并选中。每次长按只创建一页，需松开再按才能继续创建；页码按顺序自动重排，原有内容保留。最多 64 页，短按到边界不循环、不自动建页。
- 按下 I/O 时暂停自动走格，保留录制开关。左右方向键仍只在当前页的 16 格内移动；空格从当前页、当前格恢复自动播放。播放按页序连续进行，最后一页回到第一页；P 导出从第一页到最后一页的一遍完整编曲。
- 所有页面保存在同一个工程中，速度、音量等设置全工程共用。新建页和实际翻页会触发保存；重开从第一页进入。普通模式下 Delete 两次清空整个工程并恢复为 1 个空页面；逐格模式下 Delete 一次清空当前选中的单元格。
- 旧单页工程可直接打开；第一次保存为多页格式前，自动保留原文件到 `song.json.v1-backup.json`。旧版不能直接读取多页工程，回撤应用时需先另存多页文件，再从该备份恢复单页工程。备份冲突或失败时拒绝覆盖原工程。
- 自动走格和跨页的可见变化也优先提交画面，不再等 250 毫秒后台检查；慢屏仍只接收最新待显示帧，音频不等待写屏。不承诺电子纸每一格都能独立显示。

详细行为、回撤和验证范围见 [多页编曲说明](docs/multipage-0.1.6.md)。

## 0.1.1 资源与卡顿修复

- Go 运行时采用 6 MiB **软内存预算**，提前回收临时对象；这不是整个进程的 RSS 硬上限。
- 音符动画固定 32 个槽，循环事件及主循环复用固定缓冲，避免快速弹奏时反复扩容分配。
- 无声部时直接清零 PCM 缓冲，跳过每个采样的八声部计算；音频设备仍保持打开以降低下一次弹奏的启动延迟。
- WAV 导出支持取消，导出时 Home/Back 立即进入退出流程，取消未完成文件；以前导出阶段会忽略退出键。
- 新增 `last-session.json`，记录运行/退出状态、错误及运行时内存，覆盖写入且不记录用户音符。
- 本次反馈时设备仍在运行，没有发现保留的 OOM/重启证据，不能确认原卡顿是内存不足。压力测试与限制见 [故障调查记录](docs/resource-fix-0.1.1.md)。

## 现在可以做什么

- 像弹小键盘一样按键发声，支持最多八个同时发声的声部。
- 三种合成音色：PIANO（钢琴风格）、BELL（钟声）、CHIP（柔和电子音）。它们不是钢琴采样。
- 四种合成鼓声：底鼓、军鼓、踩镲、拍手；不依赖外部声音素材。
- 琴键短按保留提示、固定音名和鼓声指示、16 格循环进度。
- 录制多页编曲，每页八拍／16 格，可边播放边继续添加音符和鼓声。
- 本地自动保存，重新打开继续编辑；可以导出标准 WAV 文件。

## 按键

旋律键从低到高依次为：**`A W S E D F T G Y H U J K`**，覆盖一个半音完整排列的八度（含两端 C）。例如 `A/S/D` 是 C/D/E，`W/E` 是对应黑键。

- **Q**：切换音色。
- **C / V / B / N**：底鼓 / 军鼓 / 踩镲 / 拍手。
- **Z / X**：降低 / 升高八度，范围 C3 到 C6 起始八度。
- **R**：开始或停止录制。开始时自动走格；若从逐格浏览状态开始，则从选中格自动走格。再次按 R 只结束录制：自动循环继续播放，逐格模式则留在当前格。已有循环保留，新音符叠加进去。
- **空格**：逐格模式下，从当前页、当前格恢复自动循环，保留录制状态；自动录制时按空格暂停自动走格并保留录制开关，再按可从当前格继续，按 R 结束录制。不在录制时按空格停止播放，再按从当前页第 1 格播放。自动播放依次跨页，最后一页之后回到第一页。
- **I / O 短按**：切到已有的上一页／下一页，选中该页第 1 格；在首尾停住，不自动建页。按下即暂停自动走格，录制开关保持不变。
- **I / O 长按约 0.7 秒**：在当前页左侧／右侧插入空白页并选中，新页第 1 格起步；序号自动重排，原有内容随页保留。一次长按只插入一页，最多 64 页。
- **左右方向键**：切换到逐格模式，停止自动走格，左退一格、右进一格，只在当前页内首尾循环。已经进入逐格录制后按住琴键向右移动可延音；向左或页内首尾循环不延音。不在录制时只浏览和试听，不会暗中开启录制；从未选过格子的空闲状态首次拨动选中第 1 格。
- **上下方向键**：上加速、下减速，每次 5 BPM，范围 60–180。自动播放时保持当前格和格内进度，逐格时不会移动光标。
- **独立音量键**：调整应用内部音量，每次 5；不擅自覆盖设备硬件混音器设置。
- **Enter / OK**：立即保存；停止修改约两秒后也会自动保存，正常退出时会保存剩余修改。
- **P**：将完整编曲从第一页到最后一页导出一遍 WAV（末尾保留一秒尾音空间），保存在本机 exports 目录。导出时暂停弹奏及循环，完成后即可继续；Home/Back 可以取消导出并退出。
- **Delete**：逐格模式下第一次按 Delete 清空当前选中的单元格；如果在两秒内再次按 Delete，则清空整个工程并恢复为 1 个空页面。普通模式下连续按两次 Delete 也会清空整个工程并恢复为 1 个空页面。
- **L**：打开或关闭帮助。
- **电源键**：应用内不执行退出或音乐操作，交由支持长按关机的核心处理；正常使用无需先返回主页。
- **Home / Back**：退出并释放键盘、显示和声卡，回到原界面。

设备没有普通 PC 的全部数字键、Tab 和斜杠键，所以主操作全部采用已核实存在的实体按键。外接键盘的数字 1–4、Tab、斜杠、Backspace 仍提供对应兼容操作。

最快开始：按 R → 用 A/S/D/F/G 弹几下，或按 C/V 打鼓 → 再按 R，刚才的旋律就会循环播放。按 P 可以导出。

逐格录制：按 R → 拨左／右停住并选格 → 弹琴或打鼓填入这一格 → 按 Delete 可清空当前格 → 拨左／右换格继续填 → 按空格从当前格边循环边继续录 → 按 R 结束录制。录制停止后，弹奏只试听，不再改工程。逐格时同一格可放多个不同音符和鼓声，最多 8 个。

## 保存位置与当前范围

- 设备工程：`/storage/c1/pinao/song.json`。
- 设备导出：`/storage/c1/pinao/exports/pinao-日期-时间-编号.wav`。
- 可以通过 `--song <路径>` 或 `PINAO_DATA_DIR` 指定隔离的工程位置，测试不会混入用户工程。
- 程序安装在包管理器的版本目录内，用户工程独立存储，更新软件不会替换录制内容。
- 工程写入使用临时文件、同步、原子替换；已有工程格式损坏时拒绝覆盖，保留原文件供恢复。

这是轻量编曲工具，不是完整桌面音乐制作软件：目前只有一个工程，可含 1–64 页，每页固定八拍/16 格，每格最多八个音符或鼓声；记录的是量化到八分音符格点的触发、音色和逐格延音，不保存自由时长的按键力度/延音，不录制麦克风，也没有多轨剪辑或混响。八声部由旋律和鼓共用，超出时替换最早声部；单次持键最多约八秒后自动释放，避免漏松键持续鸣响。

按键、走格和跨页变化优先提交画面，其他后台状态最多每 250 毫秒检查一次；静止画面不重复绘制或写屏，慢屏只保留最新待显示画面。电子纸的实际刷新速度低于普通 LCD；音频合成、键盘读取、慢速写屏分开处理，不承诺高帧率或每次短按都能物理独立显示。程序退出后才释放声卡；使用时会阻止系统把它当作空闲桌面自动休眠。

## 本地开发与构建

需要 Go 1.26.4 或兼容版本；构建脚本使用原生 Go 工具核验 ELF，不依赖 WSL 的 `file`、`readelf`。Linux/WSL 用于额外的 race 检查。设备音频使用系统现有 `/usr/bin/aplay`。唯一 Go 外部依赖为 `golang.org/x/sys/unix`。

```powershell
cd D:\c1slim\Pinao
go test ./...
go vet ./...
.\build.ps1 -Version 0.1.6 -OutputPath build/multipage-0.1.6/pinao
```

构建输出 `build/pinao`，目标为 Linux/mipsle、hardfloat、静态 ELF。脚本在构建前执行主机测试和 vet，构建后核验 MIPS ABI。Linux/WSL 另执行 `go test -race ./...`。

无需设备也能生成预览和演示声音（目标文件必须不存在）：

```powershell
go run . --preview build/my-preview.png
go run . --demo-wav build/my-demo.wav
go run . --song path/to/song.json --export-wav build/my-loop.wav
```

`--version` 和 `--help` 不打开屏幕或声卡。`--smoke-test` 在设备上播放约六秒、较低软件音量的内置演示，不写用户工程；其他未知参数会报错。

## 发布与安装

开发者请从本仓库的 [开发者工具 Release](https://github.com/fwz233-RE/C1ancher/releases/tag/developer-kit-20260907) 下载发布工具，按 [统一发布说明](../docs/publishing.md) 使用 `-binary` 上传构建后的 `build/pinao`。

`pinao` 是现有受保护应用 ID。研究源码后发布自己的修改版，应选择自己的新 ID；`-open` 不能覆盖官方 Pinao。把确定的版本号传给 `build.ps1 -Version`，确保编入程序的版本和上传参数一致。

HTTP 上传需显式接受明文风险；应用上传后由用户在设备包管理器刷新并选择安装，不会自动安装到所有设备。
