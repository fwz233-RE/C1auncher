# Pinao 0.1.1 资源与卡顿修复记录

日期：2026-09-06。用户反馈 Pinao 使用后设备像崩溃；设备仍可通过 ADB 连接，连续开机约 45 小时，当前核心、监督程序和启动器均正常。故障现场没有发现 OOM（内存不足）、被杀进程、段错误、内核 panic 或设备重启，因此不能把原现象确定为内存耗尽。

## 已确认的现象和修复

旧版确认存在导出 WAV 期间忽略 Home/Back 的问题；快速输入时，动画和循环命令也会反复分配临时切片。原版已有异步最新帧写屏和 4096 字节音频管道，这次继续保留，不算新增修复。0.1.1 的处理如下：

- Go 运行时设置 6 MiB 软内存预算、50% GC 目标；它限制 Go 堆增长，不是整个进程 RSS 的硬上限。
- 音符动画固定 32 个元素，循环命令固定 9 个元素，主循环固定 10 个命令元素；快速弹奏不再依赖这些路径的重复扩容。
- 合成器没有活动声部时直接清零 PCM，跳过八声部逐采样计算。
- 音频管道固定为 4096 字节，不沿用旧游戏约 1 MiB 的积压方式，降低快速按键后声音延迟越来越长的风险。
- 保留原有独立最新帧写屏和每秒最多四帧的提交限制；初次全刷仍同步进行，驱动永久阻塞下的退出等待尚未解决。
- 导出每个 PCM 块检查取消；Home/Back 在导出期间仍然有效，取消时删除未完成 WAV，不覆盖既有文件。
- 运行记录只保留一个 `last-session.json`，只写版本、时间、状态、错误和运行时内存，不写用户旋律；错误文本最多 4096 字节。
- 按键输入收到 `SYN_DROPPED` 时清空 held 状态并发送 `off-all`，避免输入丢失后持续发声。

## 验证结果

主机 Windows 测试、Go vet、Linux race、MIPS hard-float 构建和资源回归全部通过。设备连续 65 秒执行 638 轮多键和弦、鼓声、帮助和音色切换、初始音量调整和保存导出：

- 旧版峰值 RSS：4860 kB。
- 0.1.1 候选峰值 RSS：4328 kB，约下降 10.9%。
- 候选测试最低可用内存：约 18.4 MB，没有 OOM、重启或提前退出。
- 0.1.1 候选的导出中 Home 取消通过；退出后 PCM 状态为 `closed`，键盘独占释放。
- 0.1.1 已通过仓库发布并安装，设备版本检查返回 `pinao 0.1.1`，启动演示通过。

## 结论边界

这次结果证明内存和正常操作路径得到改善，但没有证明原故障一定由内存引起。设备总内存约 50 MB、无交换分区；诊断时仍有约 29 MB 可用内存。后续若再次出现黑屏或完全无响应，需要记录现象是画面冻结、声音卡住、返回桌面还是实际重启，因为这四类问题分别对应电子纸驱动、ALSA 播放、应用退出和系统内核。

尚未把故障注入到声卡消费者停读、电子纸驱动永久阻塞、文件系统 `fsync` 阻塞这三种异常场景；这些场景可能让正常的清理等待变慢。0.1.1 先解决了已观察到的内存增长和导出退出失效问题，没有进行物理重启或断电操作。
